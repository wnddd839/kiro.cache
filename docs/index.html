01 /
Capabilities

使用更连贯，
记录更清楚.

从会话连续性到用量记录，把容易忽略的使用细节放在一起。支持个人与小团队在本机管理自己的使用环境。

兼容熟悉的工具

PROT-01

同时说 /v1/messages（Anthropic）、/v1/chat/completions 与 /v1/responses（OpenAI）。 流式 / 非流式、工具调用、reasoning 全支持；路径前缀容错，客户端 base URL 带不带 /v1 都能用。

把 prompt cache 命中率打上去

CACH-02

会话粘号 + 稳定 conversationId + 前缀修复：剥离 Claude Code 每次都变的 x-anthropic-billing-header、 工具声明排序，支持的模型使用原生思考参数，预算不再写进文本前缀。同一会话优先使用原号，忙时排队而非借号；保留历史图片，规范工具与 JSON 顺序。

账号与运行状态

POOL-03

浏览器 OAuth（Google / GitHub / Builder ID / IdC）、导入 Kiro IDE 凭证、手填 token / API key。 单飞 refresh、冷却、额度轮询；窗口内多数号同类失败判为全局故障，只冷却不停号，任一请求成功即解除。

用量与两本账

CRED-04

按 Anthropic 官方规则在本地模拟 cache read / write，按 Kiro credits 折算上游成本； 对下游收费（Claude 官方价）与上游成本分开记，管理台按 key / 号 / 模型 / 天显示毛利率与亏损。

一键生成 API Key

KEYS-05

管理台「接入」页直接生成下游 key，明文只显示一次，服务端只存 sha256。 客户端带 x-api-key 或 Authorization: Bearer 即可。

上游行为可探测

PROB-06

内置 probe 子命令直打上游，实测 token 上报口径、缓存存活时间、显式 cachePoint 是否生效、 credits 折算系数；analyze 给出可直接贴进配置的结论。

04 /

          
Getting Started

          
三步跑起来.

        


        

          

            
01 /

            
登录并加入号池

            
运行 kiro-proxy login 走浏览器 OAuth（Google / GitHub / Builder ID / IdC），或用 import-ide 导入 Kiro IDE 当前登录。可重复加多号。

          

          

            
02 /

            
启动并生成 API Key

            
直接运行 kiro-proxy，默认监听 127.0.0.1:8787。打开管理台 http://127.0.0.1:8787/ui，在「接入」页一键生成 API Key。

          

          

            
03 /

            
配置下游工具

            
Claude Code 填 ANTHROPIC_BASE_URL=http://127.0.0.1:8787；OpenAI SDK / Cursor 等填 http://127.0.0.1:8787/v1，带上 API Key。
