# 上游前缀稳定性审查与 Sonnet 5.5 实测

2026-10-08，模型 `claude-sonnet-5.5`，同一本地账号。通过本项目真实 HTTP 服务入口调用 Kiro，每次发送前保存实际请求字节；全部使用人工参考文本和生成的测试图片，不含业务对话。本记录不包含账号或凭据。

## 九项审查结论

| 检查项 | 结果与处理 |
|---|---|
| 思考预算 | 支持 schema 的模型使用请求根部原生字段，文本不含预算标签。旧模型保留首次预算，修复并发首次请求的 get/set 间隙，避免同一线程首次请求钉住不同值。 |
| 换号 / 钉号过期 | 首次答复前为在途请求保留临时账号选择，不提前提交正式钉号；并发首请求也使用同号。钉住的账号忙时最多等待 3 秒，然后返回 429 + Retry-After，不借用其它账号。失败、冷却、禁用等真正不可用时仍换号。默认会话空闲保留期从 45m 延长至 24h，查到活跃钉号会续期。没有统一的结束信号，仍保留空闲过期与 4096 会话容量上限。 |
| system 变化 | 不注入当前日期、不改写客户端 CLAUDE.md 等内容，只按既有规则删除 billing header 及用户配置的 system 正则。相同 system 不变，真正变动如实发送并会影响前缀。明确的客户端 session 可以跨此类变化保存调试比较记录。 |
| 工具声明 | 默认按名字排序。发现 RawMessage 的 schema 键顺序会原样保留，现已递归规范 JSON 对象键顺序，数组顺序和数值精度保留。历史缺失工具占位固定为 Tool / 空 object schema，补充列表按名字排序。客户端真实增删、修改工具声明仍会改变工具前缀。 |
| 历史转换 | 连续同角色合并、空消息占位、tool_result 配对和截断规则固定。tool-use input 也规范 JSON 键顺序。旧思考块始终不转发；会话 lineage 和本地缓存指纹同步忽略不转发的思考块，避免仅思考文本或签名变化使 conversationId 轮换。 |
| 图片 | 发现原实现只留下最新一批图，新图会删除历史图片。已改为全部历史图片随原消息重发，新增图片不改旧消息。 |
| 会话 ID | 同线程同账号保持 conversationId；改写历史时轮换。与本地缓存状态一起落盘恢复。 |
| 随机 / 时间 | uuid 用于 conversation / 请求头 / 管理记录，不注入 prompt 正文。正常会话 conversationId 固定；random 模式仍明确用于对照。 |
| map 遍历 | Prompt 构造未从随机 map 遍历直接拼文本。普通 map 交给 encoding/json 时对象键排序；已补上此前绕过排序的 RawMessage。历史工具去重 map 仅作查询，不用其遍历顺序生成声明。 |

“文本一样”是命中的必要条件之一；账号、模型参数、工具和上游 TTL 也可能影响缓存，不能仅凭逐字节稳定承诺必命中。客户端如果更改早先消息、system 或工具，服务不会为保命中而悄悄冻结旧内容。实验性的 `cache_points` 默认关闭；其中 assistant 断点会随最新历史回复移动，启用时诊断可能报告相关 metadata 变化，不能据此声称正文必命中。

## 调试开关

配置：

```json
{
  "debug_requests_dir": ".cache/upstream-requests"
}
```

默认关闭。目录内保存：

- `*.request.json`：传给 Generate 的原始请求字节。
- `*.request.json.meta.json`：本次请求和上一请求的比较。
- `*.latest.json` / `*.latest.meta.json`：各客户端会话最近的请求和元数据。

文件包含完整 system、历史、工具、图片及 profileArn，不保存 Authorization 请求头；调试完成后可关闭开关、删除目录。文件按 0600 创建，目录按 0700 创建。调试 I/O 失败只记日志，不中断生成请求。目录需要按使用情况手动清理。

不能把两个完整 JSON 文件直接做文件前缀判断：协议把上一轮 current 移进下一轮 history，工具声明仍挂在新的 current，JSON 的外层位置和闭合括号因此变化。诊断在保留原始文件的同时，把 history + current 按消息时间顺序序列化，独立比较当前工具声明和原生参数。**这个投影用于检查客户端侧稳定性，不声称复刻 Kiro 内部的模型 prompt。**

`messages_extend: true` 表示上一请求消息字节是下一请求的前缀（相同请求也成立）；`common_message_bytes` 是相同长度；不延续时 `first_different_byte` 是从 0 开始的第一个不同字节，位置对应投影后的消息序列。`same_account / same_conversation / same_model / same_parameters / same_tools` 独立报告其它变化。

## 文本、工具与 JSON 顺序

约 3500 token 的参考文本，加一个不实际调用的工具。轮次 2 交换工具 schema 对象键顺序，规范化后实际发往上游的工具字节不变。后续把真实回复 `ok` 加入历史再追加提问，原生 effort 始终为 low。

| 次序 | 场景 | credits | 消息前缀 | 工具、账号、会话和参数 |
|---|---|---:|---|---|
| 1 | 首次请求 | 0.1054612147 | 无前一请求 | 初始状态 |
| 2 | 相同请求，schema 换键顺序 | 0.0289998714 | 完全相同 | 不变 |
| 3 | 追加回复与下一条问题 | 0.0293663722 | 延续 | 不变 |
| 4 | 再追加一轮 | 0.0294030223 | 延续 | 不变 |
| 5 | 修改 system 开头 | 0.1057483788 | 第 32 字节不同 | 同账号，conversationId 轮换 |

第 3 / 4 轮对应的消息比较为 `14271 → 14431 → 14591` 字节，分别完整保留之前的 14271 / 14431 字节。成本变化支持稳定前缀维持了上游暖状态；system 改动的对照恢复冷请求成本。

## 历史图片

使用 Go 标准库生成 64×64 PNG。第一轮带图片，第三轮追加一条带新图片的消息，旧图片仍在 history 中，字节保持不变。

| 次序 | 场景 | credits | 消息前缀 |
|---|---|---:|---|
| 1 | 首次带图 | 0.1083647636 | 无前一请求 |
| 2 | 同一带图请求 | 0.0297846143 | 完全相同 |
| 3 | 保留旧图并追加带图一轮 | 0.0303882628 | 延续，完整保留此前 14542 字节 |

最初使用另一份极小 PNG 样本时，上游返回 `IMAGE_FORMAT_UNSUPPORTED`；换为标准库生成的图片后三次均 HTTP 200。因此该失败不作为前缀或历史图支持的证据。

## Sonnet 5.5 原生 effort

同一文本、工具、账号和 conversationId，5 次消息序列 SHA-256 完全一致。

| 顺序 | effort | credits |
|---|---|---:|
| 1 | low | 0.1062349626 |
| 2 | low | 0.0292089924 |
| 3 | high | 0.0292089924 |
| 4 | high | 0.0292089924 |
| 5 | low | 0.0292089924 |

本组切换 effort 后仍呈暖请求成本。这与先前 [Sonnet 4.6 实验](native-thinking.md) 的首次切强度变冷现象不同。测试任务只需回复 ok，没有可见思考输出；不能据此断言更复杂任务或所有模型都复用跨强度缓存。本地计量继续按原生参数保守隔离，因此首次 high 的模拟 cache_write 不等于本次上游实际成本变化。

## 验证范围

本地 HTTP 端到端回归覆盖：新增图片不删除旧图、schema 键顺序变化、工具排序、历史 thinking / 签名变化、tool-use input 对象键顺序、tool_result 轮次、实际调试文件与上游收到的字节一致、system / 工具 / effort 变化分类、旧模型并发首次预算、并发首请求同号且不提前正式钉号、账号忙时不借号以及不可用时仍失败切换。

真实上游成功场景共 13 次生成，均 HTTP 200；上游仍未直接报告 cache token，credits 是缓存行为的间接证据。完整原始请求和结果保存在本地 `.cache/prefix-audit/`，不提交账号相关快照。
