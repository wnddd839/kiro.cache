缓存策略

同一会话粘在同一个号上（session_ttl 内），并为会话生成稳定的 conversationId；请求前缀做修复与规整（sort_tools 排序工具定义、pin_thinking 固定 thinking 配置），保证上游前缀字节一致，以便命中 prompt cache。换号重试会丢失该号上的缓存。

命中率口径

命中率 = cache_read / (input + cache_read + cache_write)，按 token 计。input 为未命中缓存的输入部分。首轮请求只会产生 cache_write，命中率低属正常；多轮对话后应持续上升。

添加账号

浏览器登录、导入本机 Kiro IDE 凭证，或手动填写 token。

服务端在本机打开登录页（IDE 式 OAuth），完成后自动入池。
